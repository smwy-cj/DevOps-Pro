# E9 重复 MD 去重决策记录

姓名：庄子宣；学号：241880258；轨道：B；日期：2026-11-03。

## 问题与目标

我在 direct、macro、mixed 三种风格中重复提供同一条 MISSING main.o/config.h，发现原实现会追加两次 config.h，plan 也会生成两项。我的目标是让同一条缺失依赖只生成一次修复，并保持原文件不变。

## 方案选择

我在 patch() 每次调用中建立 seen 集合，使用 (target, dependency) 作为去重键。第一项通过原有检查并生成修改后记录，后续重复项跳过，保留首次出现的顺序。额外空间随唯一 MD 数量增长。

我考虑过只按 dependency 或 target 去重，但前者会丢失不同目标对同一依赖的修复，后者会丢失同一目标的其他缺失依赖，因此选择完整边去重。

## 行为与覆盖范围

我保留了报告提交校验、路径检查和三种风格的定位方式。只为 MISSING 生成候选，保留 REDUNDANT 和编译配方；生成时不改写原 Makefile，验证全部通过后才写回。

我使用课程 Dockerfile，在 WSL Linux 中运行容器。报告 commit 对应内层样例 HEAD，student-source-commit.txt 对应外层源码版本，两类版本分别保存。

此次去重针对报告中完全相同的边，不处理路径别名归一化。共享变量被多个目标使用时的影响分析不在本次扩展范围。

## 验证结果

我通过三种风格的重复 MD 用例确认：只追加一次依赖、plan 只有一项、原 Makefile 字节不变。不同目标和不同依赖的对照用例也通过，合法修复没有丢失。全部 12 项测试及 B 组 E8—E10 回归通过，原始结果见个人报告和 work/e9-duplicate-md/。
